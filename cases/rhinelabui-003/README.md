# RhineLabUI 案例 003：单列布局拖动时选中列跳跃

- 仓库：<https://github.com/sakura4388/RhineLabUI>
- 基线：`6394b3c6a203ad687d535071cecd6bcce3447ff2`，加上本地栏目校验与循环检查修复
- 状态：浏览器复现后已在本地修复并验证，尚未提交或推送
- 环境：Windows、Node.js v24.19.0、Microsoft Edge 无头浏览器、1920×1080 视口；隔离工作树 Vite 本地服务 `http://127.0.0.1:5204`

## 复现

启动隔离工作树的本地服务后，设置 `PLAYWRIGHT_MODULE` 为本机 Playwright 模块目录，在 Code Defog 仓库执行：

```powershell
node cases/rhinelabui-003/verify-drag.mjs
```

脚本打开 `/?scene=archive`，等待场景就绪，读取实际相机投影方向，在画布上按该方向拖动 0.8 列距离。修复前，预期从逻辑第 0 列选择第 1 列；实际轨道移动约 4.16，即 0.8 个列间距，但 `selectedCell.lane` 变成 3。断言 `3 !== 1`，脚本退出码 1。设置 `DRAG_LANES=0.2` 时，预期仍在第 0 列，实际跳到第 2 列，断言 `2 !== 0`。两次均无页面异常。

## 原因和影响

修复前，`src/scene.ts` 的初始选中列按当前列数设为 `0`，单列档案的位置换算也以 `0` 为中心；但 `trackCoordinate("lane", value)` 仍加 `2`，`trackPosition()` 仍减 `2`。例如移动 0.8 列时，坐标被算成 `4.16 / 5.2 + 2 = 2.8`，四舍五入后选中第 3 列。单列内容会循环复用，因此未必出现不同档案，但选中位置与画面轨道不一致。

本地修复把场景位置、拖动坐标和惯性轨道都统一到 `(archiveColumns.length - 1) / 2` 计算出的中心。五列时仍为 `2`，单列时为 `0`。

修复后同一 `verify-drag.mjs` 在 0.8 和 0.2 列距离下均退出码 0：拖动时分别选中列 1 和 0，松手吸附后 `columnCamera` 分别为 5.2 和 0。`verify-fling.mjs` 的快速释放检查也以 0 退出：释放时惯性列坐标约 0.8002、轨道约 4.161；250 毫秒后轨道继续移动；最终选中列 2、轨道 10.4，二者对齐。浏览器无页面异常，隔离工作树 `npm run build` 通过。

随后用 `verify-touch.mjs` 的 Edge 触控模拟复核 390×844 竖屏及 844×390 横屏。两种视口的 0.2 列拖动均保持第 0 列并吸附到轨道 0；0.8 列拖动均选中第 1 列并吸附到轨道 5.2；快速滑动释放后均进入 `coasting`，最终选中列与轨道对齐。六组检查全部通过，页面无异常。这是浏览器触控模拟，并非实体手机或 Safari 实机验证。
