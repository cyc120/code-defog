# Code Defog — Test Suite and Peripheral Code Review

**Scope reviewed:** tests/ (14 files, ~4,700 lines), scripts/ (update_worklog.py 782L, watch_worklog.py 318L, scan_code_map.py 127L, event_client.py 63L), tools/controlled_repair.py (189L), retrospective/ (retrospective.py 111L, skills.py 487L), README.md + docs/, requirements.txt. Every finding carries an exact file:line.

**Ground truth:** the full suite was executed — python -m pytest tests/ -q -x → **233 passed + 4 subtests in 42.93s**. All README claims were spot-checked against daemon code (auth headers, approval grants, key storage, binding, drive timeouts, test-promotion rules, artifact hashing). Where a sub-agent finding was overstated, it was corrected against direct reads.

---

## 0. Overall verdict

The suite is genuinely **assertion-heavy, well-isolated, and security-focused** — not smoke-tested. Approval-flow, key-redaction, exfiltration-prevention, path-escape, and fail-closed boundaries carry real assertions at both store and HTTP layers; every test uses its own TemporaryDirectory + fresh StateStore; no test touches the real network or a real LLM key. **No critical findings.** The material problems: (1) production-critical watch_worklog.py (the daemon change-detection engine) has zero tests and three lost-change bugs; (2) a few timing/sleep-based tests are flaky or slow; (3) several fail-closed branches of the approval-grant and LLM-transport code are untested, and one (malformed LLM 200 response) crashes the endpoint; (4) a restart-durability test overclaims; (5) duplicated fixtures across 8 files are a maintenance hazard.

## 1. Test quality — findings

- **[SEVERITY: high] tests/test_daemon.py:2014,2030** — test_case_creation_pushes_sse uses unconditional time.sleep(0.3) x2 to wait for an SSE connection, and the listener thread (1996-2008) swallows every exception. If the event arrives before the subscription or after the second sleep, the test fails intermittently under CI load. **Fix:** signal a threading.Event on connect/receive and wait on it with a timeout instead of sleeping.
- **[SEVERITY: high] tests/test_daemon.py:1103-1203** — test_completed_handoffs_auto_advance_and_survive_orchestrator_restart never actually restarts anything: a new Orchestrator is built over the **same** StateStore/SQLite connection (1196), so crash/restart durability (reopen the DB file, re-read agent_runs, resume) is untested. **Fix:** close and reopen StateStore(database) between the two orchestrator instances and assert the resumed context comes from the reopened DB.
- **[SEVERITY: high] scripts/watch_worklog.py — completely untested** (grep confirms no test imports it). It is production code: daemon/project_monitor.py:31 imports its snapshot/diff_snapshots engine, and update_worklog_safe (212-219) spawns update_worklog.py as a subprocess. The three lost-change bugs in section 3 would all be caught by unit tests for diff_snapshots / run_once / run_forever. **Fix:** add tests for snapshot/diff (add/modify/delete), run_once with empty/corrupt/existing state, and update_worklog_safe on CalledProcessError.
- **[SEVERITY: high] daemon/llm_summary.py:148** (production bug surfaced by the wire-test gap) — the response parse `payload["choices"][0]["message"]["content"]` raises KeyError/IndexError/TypeError on a 200 response with wrong shape (e.g. an empty choices array). Callers (llm_summary.py:300-301, code_semantics.py:183) catch only HTTPError/URLError/OSError/socket.timeout/JSONDecodeError, so a malformed provider response crashes the endpoint instead of returning status:error. No test covers it. **Fix:** guard the extraction and raise a caught type; add a wire test with an empty-choices body.
- **[SEVERITY: high] Path containment / traversal — untested.** No test exercises the artifact-URI containment logic (store.py:1207-1216 _artifact_target, 1272-1277 read_artifact root check) with a malicious input (e.g. uri=../../../etc/passwd or a DB row carrying an absolute URI), nor caller-supplied workspaces on management endpoints: delete_session (store.py:527-534) accepts any resolved absolute path — a client knowing another workspace path can clear it (only the service token guards it). **Fix:** tests that (a) a crafted URI/DB row cannot read outside the artifact root, and (b) management endpoints reject/contain out-of-root workspaces.
- **[SEVERITY: high] Crash recovery / concurrency — untested.** No test that two threads ingest concurrently without corrupting state (single connection under RLock, store.py:114,118), no test that a mid-transaction exception (between grant-marked-used and state update, store.py:870-899) leaves the DB consistent, and no test that a NEW StateStore over the same file sees prior committed state (the restart test at :1103-1203 reuses the same connection — see the separate high finding above). **Fix:** add concurrent-ingest, mid-transaction-failure, and fresh-StateStore-reopen tests.
- **[SEVERITY: medium] tests/test_daemon.py:1308-1341** — test_missing_patch_ref_escalates_after_gate_pass reaches ESCALATED via direct store.transition_case (1338), bypassing the orchestrator escalation logic (orchestrator.py:190-211). ## 3. scripts/ — robustness findings

### update_worklog.py (atomicity, crash safety, diff)
- **[SEVERITY: medium] update_worklog.py:727 vs 759** — the file is read twice (load at 727/434, re-read at 759) and the section built from the *first* read is spliced into the *second* read content (760): a concurrent updater (the watcher spawns this on every change) can lose rows. **Fix:** single read, or re-read at write time and retry replace_section on content change.
- **[SEVERITY: medium] update_worklog.py:434,759** — a corrupt/non-UTF-8 worklog crashes with an uncaught UnicodeDecodeError (missing-file is handled at 428-433; corrupt content is not). **Fix:** try/except, back up the corrupt file, start from defaults.
- **[SEVERITY: medium] update_worklog.py:501-510, 688-696** — marker mismatch: a file with only START duplicates the whole section on the next run; END-before-START raises uncaught ValueError at 695. **Fix:** treat mismatched marker pairs explicitly.
- **[SEVERITY: low] update_worklog.py:715** — no parent-directory fsync after os.replace (rename not durable across power loss). **Fix:** fsync the parent dir.
- **[SEVERITY: low] update_worklog.py:734-742** — --note/--phase always appends a timestamped live note; re-running the same command (or a watcher retry) duplicates notes. **Fix:** last-note match key or documented log semantics.
- **[SEVERITY: low] update_worklog.py:342,357** — newline-to-<br> round-trip corrupts values that literally contain <br>. **Fix:** sentinel or entity escaping.
- **[SEVERITY: low] update_worklog.py:221,725-726** — --workspace defaults to the current dir and is never validated to be a directory (unlike watch_worklog.py:308-309); pointing it at a file yields a confusing mkstemp traceback. **Fix:** validate workspace.is_dir().
- **Verified good:** atomic_write_text (699-720) is genuinely atomic (same-dir mkstemp, fsync, mode preservation at 713-714, os.replace, finally-cleanup); merge_unique prevents duplicate file/module rows on rerun; newline sanitization in render paths is real and tested (test_scripts.py:113-123).

### watch_worklog.py
- **[SEVERITY: medium] watch_worklog.py:246, 289-290** — state is saved **before** the updater runs; if the updater exits non-zero, update_worklog_safe swallows it (217-219) but the snapshot already advanced, so the change is never retried and never reaches the worklog. **Fix:** persist state only after a successful update.
- **[SEVERITY: medium] watch_worklog.py:91** — save_state is a plain write_text (not atomic); a crash mid-write corrupts the file, load_state silently returns empty (76-77), and run_once treats it as a fresh baseline (230-231), suppressing real pending changes. **Fix:** reuse the temp+os.replace pattern.
- **[SEVERITY: medium] watch_worklog.py:66-68** — watcher state (full workspace paths + file mtimes) lives in world-readable /tmp/code-defog/, contradicting the daemon per-user ACL posture (daemon/paths.py:84-86). **Fix:** use daemon.paths.monitor_state_dir() with 0o700.
- **[SEVERITY: medium] watch_worklog.py:130-133, 149** — change detection is mtime_ns+size only: a size/mtime-preserving rewrite is never reported, and two writes in the same tick conflate. This propagates to the daemon monitored-project events (project_monitor.py:31-32). **Fix:** add a content-hash or inode/ctime component.
- **[SEVERITY: low] watch_worklog.py:266** — run_forever never loads persisted state: changes while the watcher was down are lost, and two concurrent watchers double-report. **Fix:** load at startup (with a claim marker).
- **[SEVERITY: low] watch_worklog.py:302** — previous = current even when the update failed, compounding the lost-change bug. **Fix:** only advance on success.
- **[SEVERITY: low] watch_worklog.py:217** — update_worklog_safe catches only subprocess.CalledProcessError; an OSError on spawn kills the loop. **Fix:** except Exception.
- **[SEVERITY: low] watch_worklog.py:169-209** — one full Python subprocess per change event with ~100+ argv bytes per --touch; heavy at high change rates. **Fix:** call the updater in-process or batch.
- **[SEVERITY: low] daemon/project_monitor.py:104** — state_file is allocated in the global state dir but never used (the snapshot call passes /dev/null at 151); dead code that would leak state files if activated. **Fix:** remove or wire it per-test-temp.

### event_client.py

- **[SEVERITY: low] scan_code_map.py:53-62** — nonexistent input paths silently produce header-only output with exit 0. **Fix:** warn to stderr, exit non-zero.
