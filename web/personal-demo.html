03 / 审查发现

发现 1 个需要处理的问题

先看证据，再看建议。点击左侧条目可以切换查看。

问题清单

问题证据

失败发生在哪里

示例输入 no_projects.json 有必需字段，但没有 projects。直接按键读取会触发异常。

# demo_target/cli.py
return {
  "projects": config["projects"],
  "required_field": config["required_field"],
}
预期未配置项目时返回空列表，CLI 正常退出。实际抛出 KeyError: 'projects'，CLI 退出码为 1。
回归证据

不能把验证一并放宽

如果修复时给 required_field 也填入默认值，缺失必需字段的配置就可能被错误接受。

# 应保留的规则
if not config["required_field"]:
  raise ConfigError(...)

缺少 required_field → 验证失败
验证门禁同时检查“缺少 projects 可正常处理”和“缺少 required_field 必须报错”。
04 / 由你决定

建议这样修复

个人版先让你看懂改动和影响，再决定是否执行。此处的选择仅改变演示结果。

待确认方案

只给可选字段设置默认值

让 projects 缺失时成为空列表；保留 required_field 的必填验证。

- "projects": config["projects"],
+ "projects": config.get("projects", []),
  "required_field": config["required_field"],

验证时应该检查

01 缺少 projects 时正常返回空列表
02 缺少 required_field 时仍报错
03 正常配置仍能列出项目
真实修复需要在隔离副本中执行、记录 diff 与测试输出，并由你确认后再应用到项目。
